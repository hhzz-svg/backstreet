## 0. 一句话结论

**没有一个开源项目能直接拿来当"巷战枪战游戏"的成品**，但存在两条成熟的组装路线：

- **Web 路线**：`three.js` + `Rapier` + `three.quarks` + `pmndrs/postprocessing`，参考实现 **mshumer/Claude-of-Duty**（MIT，已实现 TAA / 动态模糊 / Karis Bloom / 体积光 / GPU 粒子 / 曳光弹 / 贴花的完整 COD 级管线）。
- **原生路线**：**AssaultCube**（本身就是"贴近真实环境的近距离交战 FPS"，zlib）作为玩法与网络代码参考，**Godot 4 + KenneyNL Starter-Kit-FPS**（MIT + CC0）作为可商用的干净起点，**UE5 Lyra** 作为品质天花板。

打击感与特效**不是选引擎就能白送的**，它是一套需要自己搭的、由约 10 层同帧触发的反馈栈（详见设计方案第 3 章）。

## 3. 打击感（打击感 = game feel）核心资料

**两份必看，别跳过：**

1. **[The Art of Screenshake — Jan Willem Nijman (Vlambeer)](https://www.youtube.com/watch?v=AJdEqssNZ-U)**
   现场把一个白板射击游戏逐条叠加约 30 个"小技巧"：更大的子弹、更高射速、枪口火光、开火屏震、**命中时 ~0.2s 的 sleep（定帧）**、敌人击退、弹着粒子、永久痕迹（弹孔/尸体）、相机 lerp、音效。每条单独可开关，能直接当 checklist 用。

2. **[Math for Game Programmers: Juicing Your Cameras With Math — Squirrel Eiserloh (GDC 2016)](https://www.youtube.com/watch?v=tu-Qe66AvtY)**
   trauma 式屏幕震动的权威出处。核心：维护一个 0..1 的 trauma 标量 → 事件累加 → 每帧线性衰减 → **实际幅度 = trauma²（或³）** → 用 **Perlin/simplex 噪声**（不是逐帧随机）分轴驱动偏移 → **优先用旋转（roll/pitch/yaw）而不是纯平移**，更有劲且不晕。幻灯片：mathforgameprogrammers.com/gdc2016

## 6. 网络架构（如果做多人）

**结论已由品类定死**：专用**服务器权威** + **客户端预测** + **服务器和解** + **实体/快照插值** + **偏袒射手的延迟补偿**。
**不要**用 GGPO 式确定性 P2P 回滚——那是格斗游戏的方案。

| 资料 | 地址 | 关键点 |
|---|---|---|
| **Gabriel Gambetta — Fast-Paced Multiplayer** | https://www.gabrielgambetta.com/client-server-game-architecture.html | 四篇：①C/S 架构 ②客户端预测与服务器和解 ③实体插值 ④延迟补偿。含 <500 行的可交互 JS 演示 |
| **Overwatch 架构与网络代码（Tim Ford, GDC 2017）** | https://www.gdcvault.com/play/1024001/-Overwatch-Gameplay-Architecture-and | 默认预测**所有**移动/技能/投射物并在误判时回滚；**网络代码被 ECS 隔离在几百个系统中的约 3 个里**；固定 16ms 指令帧（60Hz，比赛模式 128Hz）；输入饥饿时服务器让客户端"膨胀时间"加速模拟以补满输入缓冲；命中回溯只回溯**空间上相交的包围体**；>220ms 改用外推。文字版：https://edgegap.com/blog/game-backend-deep-dive-overwatch-2016-netcode-architecture-rollback |
| SnapNet — 回滚 vs 快照插值 | https://www.snapnet.dev/blog/netcode-architectures-part-2-rollback/ | 明确了选型边界：服务器权威枪战 → 快照插值 + 预测/和解（CS/Apex/OW 路线） |

**AI（单人）**：
- 导航：Recast/Detour 烘焙导航网格 + crowd 避让（窄巷不扎堆）
- 普通敌人：行为树（巡逻→发现→找掩体→射击→换弹）
- 精英/小队：**GOAP**（[F.E.A.R. 的 AI，Jeff Orkin](https://www.gamedeveloper.com/design/building-the-ai-of-f-e-a-r-with-goal-oriented-action-planning)）——目标 + 对动作做 A* 规划 + 动态重规划，能涌现出侧翼包抄、压制、协同用掩体，正是巷战最需要的。现代共识：**GOAP 管高层决策，行为树/状态机管底层执行**。
