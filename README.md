# 暗巷 BACKSTREET

一条巷子、一把 AR-15、会还击的敌人，用来验证"打击感"能不能在纯 Web 技术栈里做到位。

纯 three.js + TypeScript，零外部资源——没有下载的贴图、模型或音频文件，全部程序化生成（Canvas 画贴图、WebAudio 合成音效、代码生成几何）。

## 这是什么

M0 竖切：不是一个完整关卡，是一根打穿全部子系统的"针"。目的是在投入更多内容之前，先验证核心的射击手感能不能立住。

判决标准很直接：把打击感总开关（K 键）关掉再打开，差异要明显到不需要解释。

## 打击感栈

同一发子弹命中的同一帧里，会叠加：

- **屏幕震动**（trauma-based，noise 驱动而非随机抖动）
- **定帧 hit-stop**（命中瞬间的短暂停帧，头部/躯干/击杀帧数不同）
- **击杀慢镜**
- **双弹簧后坐力模型**（快速弹起 + 慢速回落，连发时枪口累积上抬）
- **枪口火光 + 动态光源 + 火花 + 烟雾**（程序化 Canvas 贴图 + InstancedMesh 粒子池）
- **曳光弹 + 弹孔贴花**（按表面材质分派：混凝土 / 铁皮 / 木板 / 玻璃 / 血肉）
- **分层枪声**（4 body × 2 sub × 3 mech × 4 tail 随机重组，纯 WebAudio 合成）
- **命中反馈**（hitmarker / 伤害数字 / 方向性受击弧 / 手柄震动）

每一层都能在 `lil-gui` 面板（P 键）里单独开关和调参，这不是锦上添花——没有它，打击感只能靠嘴说；有了它，任何人 30 秒内就能自己听出震动/定帧/后坐各贡献了多少。

## 快速开始

```bash
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`，点击开始界面进入游戏（首次进入会有几秒钟的着色器预热）。

```bash
npm run build      # tsc --noEmit + vite build
npm run typecheck   # 仅类型检查
npm run preview     # 预览生产构建
```

## 技术栈

- **three.js** + **three-mesh-bvh**（BVH 加速射线检测，用于 hitscan）
- **postprocessing**（Bloom → 色差 → 噪点 → 暗角 → ToneMapping 管线）
- **lil-gui**（打击感调参面板）
- 纯 TypeScript，strict 模式

零第三方粒子库、零外部音频/贴图/模型资源。

## 工程约定

- **双时钟**：粒子/相机震动/后处理/UI/音频用 `unscaledDelta`；角色移动/AI 用 `scaledDelta`。hit-stop 期间前者必须继续走，否则定帧会读成"卡了"而不是"打中了"。
- **池化**：伤害数字、贴花、粒子、动态光源全部预分配复用，运行时不 `new` 网格。
- **不要用 `light.visible` 开关灯**：会触发场景内所有材质的 shader 重编译（实测单次重编译能卡住 1.2 秒）。要熄灭就把 `intensity` 设为 0。

更多细节见 [docs/M0-模块契约.md](docs/M0-模块契约.md)（各模块的接口约定）和 [docs/M0-验证记录.md](docs/M0-验证记录.md)（集成期间抓到的 bug 与性能诊断过程）。

## 已知取舍

- **未用 three.quarks**：M0 只有 3 类特效，自写 InstancedMesh 粒子池比接一个未验证的库更稳，特效大量铺开后再考虑替换。
- **未用 ECS**：实体类型只有 3 种，收益还没显现，但状态和行为已经分离，后续迁移成本低。
- **敌人命中判定简化**：敌人开枪只做朝向玩家的窄锥点积判定，不做完整射线——这一版重点是验证玩家侧的手感。

## 开发工具

- `window.__bs`：调试句柄，暴露全部子系统 + `testFire(n)` / `aimAt(i)` / `snapshot()` / `profile(seconds)`。
- `vite.config.ts` 里的 `POST /__shot` 端点：页面渲染一帧后把 canvas 转 dataURL 发过来，落到 `shots/`，用于无可见窗口环境下的视觉验证。
